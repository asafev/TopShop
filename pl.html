How playwright-stealth works
— the library, its patches, and why some are detectable
① What it patches
playwright-stealth adds ~15 JS files via page.add_init_script() — each one patches a browser property using Object.defineProperty + Proxy: navigator.webdriver → false window.chrome.runtime → mocked navigator.plugins → fake list webgl.vendor → Intel Inc. outerdimensions → realistic
② Why it still leaks
Every add_init_script() is a CDP call (Page.addScriptToEvaluateOnNewDocument) which creates window.__pwInitScripts. The CDP connection itself triggers V8 inspector serialization — detectable via Proxy.ownKeys traps. JS patches can't hide protocol-level side effects.
③ What it can't patch
Behavioral signals are immune to JS patching. A human's mousedown → popup → mouseup → change event chain on a <select> takes 300–3000 ms. Playwright's selectOption() fires change in <5 ms, skips the OS popup entirely. No JS patch can generate timing.
